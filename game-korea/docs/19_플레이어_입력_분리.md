# 19. 플레이어 입력 분리

2026-10-21. 멀티플레이 설계의 첫 구현 단계: 도보·운전·탑승·무기 입력의 출처 분리.

## 구조

```text
로컬 키/패드 → LocalPlayerInput ─┐
                               ├→ PlayerControl → Player.apply_movement
외부 월드 입력 → submit ────────┘                → Vehicle 운전
                                                → PlayerWeapons 발사·포탑
한 번의 요청 → request_action → Director / PlayerWeapons
```

Player는 PlayerControl을 하나 가진다. 기본값은 로컬 입력이고 기존 키·패드 조작을 유지한다.
Director가 차에 태우면 그 차의 control을 해당 플레이어의 control에 연결한다.
NPC 차량의 AI·추격 입력은 기존 경로를 사용한다.

- `PlayerInputCommand`: 한 틱의 지속 입력. move_world, sprint, throttle, steer, handbrake, fire, turret, aim_enabled, aim_world.
- `LocalPlayerInput`: 전역 Input을 읽는다. 도보 화면 방향을 월드 방향으로 바꾸는 것은 이곳에서만 한다.
- `PlayerControl`: 플레이어별 로컬/외부 입력 출처. 내부 명령 버퍼를 재사용해 매 틱 입력 객체를 만들지 않는다.
- `Player.apply_movement`: 명령과 delta를 받아 기존 도보 물리를 실행한다. 외부 월드 방향을 다시 화면 방향으로 돌리지 않는다.
- Director/PlayerWeapons: 로컬 이벤트는 자신의 control이 로컬일 때만 받는다. 외부의 단발 동작은 control 신호로 받는다.

## 외부 제어 사용

캐릭터가 트리에 들어가기 전에 외부 모드를 켜면 생성 직후 로컬 키를 읽지 않는다.
Player.control 객체 자체는 교체하지 않고 모드 전환 메서드를 사용한다. Director·PlayerWeapons가 이 객체의 신호를 구독한다.

```gdscript
var actor := Player.new()
actor.control.use_external()
add_child(actor)

var command := PlayerInputCommand.new()
command.move_world = Vector2.RIGHT
command.sprint = true
command.aim_enabled = true
command.aim_world = Vector2(800, 500)
actor.control.submit(command)

# 해당 플레이어의 Director/PlayerWeapons가 붙어 있어야 동작한다.
actor.control.request_action(&"enter_exit")
actor.control.request_action(&"weapon_next")

# 연결이 끊기거나 입력을 중지할 때: 외부 모드의 모든 눌림을 지운다.
actor.control.use_external()

# 로컬 조작으로 돌아온다.
actor.control.use_local()
```

외부 명령은 새 명령이 도착할 때까지 유지된다. 실제 서버를 붙일 때 입력 시퀀스·만료 시각·중복 방지·권한 검사를 추가해야 한다.
submit은 값을 복사하므로 호출자가 원본 명령을 수정해도 이미 제출한 입력은 변하지 않는다.
이동 길이와 축 범위를 제한하고 NaN/INF를 중립 값으로 처리하지만, 이는 서버 권한 검증의 대체가 아니다.

fire는 일반 무기의 지속 눌림이다. `request_action(&"fire")`는 현재 불도저 블레이드 같은 단발 도구 조작에 사용한다.
탑승/하차와 무기 변경은 request_action으로 한 번씩 전달한다. 이번 단계에는 요청 큐와 네트워크 중복 방지가 없다.

외부 aim_world는 이미 조준할 월드 지점이어야 한다. 로컬의 화면 커서→월드 변환과 사람 그림 선택은 기존 PlayerWeapons 경로에 남겨 호환한다.
외부 조준 경로는 실제 커서나 카메라 변환을 읽지 않는다. 로컬 마우스 커서 표시도 외부 캐릭터가 바꾸지 않는다.

기본 _physics_process가 apply_movement를 호출하므로 일반 외부 제어에서는 submit만 사용한다.
서버의 수동 틱/예측 재실행에서 apply_movement를 직접 호출할 경우 자동 물리 처리를 먼저 꺼 이중 이동을 막아야 한다.
외부 표시용 캐릭터가 스냅숏으로만 움직이는 단계에서는 별도로 시뮬레이션을 끄는 구성이 필요하다.

## 검증과 다음 경계

`tests/player_control_test.tscn`은 두 캐릭터의 다른 이동, 로컬 키 격리, 원본 명령 복사,
수치 검사, 입력 모드 전환, 외부 탑승·운전·하차·조준·무기 변경을 검사한다.
기존 조작과 무기·특수차량 검증도 회귀 확인한다.

PlayerRegistry, 세션/서버 역할, 네트워크 연결, 서버 권한, 원격 보간, 좌석 예약은 아직 구현하지 않았다.
Main의 리셋·개발용 차종 변경, 부업·메뉴 같은 전역 게임/UI 요청도 현재 싱글 진입점에 남는다. 서버 진입점을 만들 때 이를 플레이어별 요청과 방 관리자 권한으로 나눠야 한다.
다음 단계는 이 control을 서버가 만든 플레이어별 입력 스트림에 연결하는 2인 이동 실험이다.
