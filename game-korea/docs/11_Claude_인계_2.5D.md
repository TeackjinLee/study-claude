# Claude Code 인계 — 2.5D 강남 샘플

작성: 2026-10-11 / 작성 주체: Codex

## 사용자 요청과 현재 결론

사용자는 첨부한 ‘네온 강남역 경찰 추격전’처럼 건물의 지붕과 두 벽면이 보이는 사선 2.5D 화면을 원한다. 기존 탑다운 화면에 디테일만 추가하는 방향에서 **2D 시뮬레이션 + 사선 투영 렌더러**를 만드는 방향으로 변경했다. 제품명에 GTA2를 사용하지 않는다. 현재 임시 작업명은 ‘서울 거리 프로젝트’다.

M6는 Claude Code에서 작업 중이라는 사용자 설명을 기준으로 한다. Codex가 M6 완료를 판정한 것은 아니다. 이 문서는 작업 현황과 제안을 전달하며, 사용자의 별도 지시를 대신하지 않는다.

## 진행 수준

**독립 실행 가능한 2.5D 구조 프로토타입 구현. 최종 아트나 본편 통합 완료가 아니다.**

| 단계 | 상태 |
|---|---|
| 사선 좌표 변환·입체 건물·실제 게임 객체 표시 | 구현, 시작 화면 캡처 완료 |
| 도보 역변환·기존 탑승/운전·추격 연결 | 코드 연결, 이번 변경의 조작 시나리오 검증 미실시 |
| 네온·벽면 간판·옥상 질감 | 코드 기반 초안 |
| 모든 효과·시설·UI의 투영 일치 | 미완료 |
| 최종 픽셀 에셋·최적화·본편 통합 | 미착수 |

전체 진행률을 수치로 확정할 근거는 없다. 참고 이미지의 밀도와 품질에 도달했다고 해석하면 안 된다.

## 실행과 조작

프로젝트 루트에서:

```bash
godot --path . res://tools/isometric_sample.tscn
```

- WASD: 도보는 화면 방향으로 이동. Shift 달리기.
- F: 기존 Director를 통한 탑승·하차.
- 운전: W/S 가감속, A/D 조향, Space 핸드브레이크. 원래 VehicleMotor 사용.
- C: 추적/교차로 고정 카메라.
- V: 화면 빗줄기.
- P: 기존 WantedSystem에 사건을 전달해 경찰 추격 시작.
- B: 2.5D 씬에서는 비교 기능을 연결하지 않았다.
- 정지 미리보기 저장: `godot --path . res://tools/isometric_sample.tscn -- --preview-shot`
- 캡처: `.screenshots/m7_isometric_gangnam.png` (1280×720).
- `--capture`는 상위 2D 자동 운전 캡처를 실행하지 않도록 무효화했다.

### 좌표와 물리

표시 식은 `screen = origin + basis * (world - focus) - Vector2(0, height)`.

- basis의 X축 `(0.78, 0.39)`, Y축 `(-0.78, 0.39)`.
- 도로와 건물 footprint는 City의 실제 좌표 사용.
- 높이는 렌더러에만 존재한다. 지형 높이·입체 충돌이 생긴 것은 아니다.
- game의 Node2D 그림을 숨기고 별도 CanvasLayer(0)에 다시 그린다. 기존 HUD의 CanvasLayer와 비 화면은 유지된다.
- Player의 기본 physics callback을 샘플에서 끄고 사선 역변환한 이동 벡터로 기존 CharacterBody2D의 move_and_slide를 호출한다. 체력·충돌·Director의 input_enabled는 원래 객체를 사용한다.
- 운전 물리·AI·도로망·미션 데이터·본편 main.tscn·project.godot은 이번 작업에서 수정하지 않았다.
- 실제 Vehicle/Pedestrian 노드를 재귀 수집해 위치·색·회전·상태를 표시한다. 경찰차도 Vehicle이면 포함된다.
- 저장은 `user://isometric_sample_save_`를 사용한다. 상위 초기화는 load_on_start=false이며 일반 저장 슬롯을 불러오지 않는다.

### 가림과 정렬

- 건물은 footprint 끝점의 x+y, 동적 객체는 위치 x+y로 정렬한다.
- 조종 대상의 투영점이 건물 외곽 안에 있으면 건물을 22% 불투명도로 그린다.
- 조종 대상에는 마지막에 황색 표식을 그린다.
- 이는 임시 근사다. 큰 건물 옆의 일반 NPC·차량은 표시 순서가 틀릴 수 있다. 면 분리나 공간 관계 기반 정렬이 필요하다.

## 이번 실행에서 확인한 범위

Godot 4.7.2 / Apple M1 Pro에서 시작 장면을 실행하고 1280×720 PNG 저장, 정상 종료 및 이미지를 확인했다. 최초 실행에서 발생한 타입 추론 오류와 동적 City 호출의 typed array 오류는 수정했다. 최종 캡처 실행에는 오류 출력이 없었다.

이번 변경에는 자동 테스트를 추가하거나 실행하지 않았다. 도보·탑승·추격·사망·저장 등 전체 시나리오가 검증되었다고 해석하면 안 된다.

이전 탑다운 첫 샘플 시점에는 회귀 9개 중 7개 통과, traffic과 vehicle_damage가 실패했다. 세부 내용은 `tools/visual_sample/README.md`와 `.screenshots/m7_validation.log`. 이번 2.5D 변경에 대한 테스트 결과가 아니며 원인도 해결하지 않았다.

## 남은 작업과 주의점

1. **표시 누락:** 신호등 상태, 탄환/총구/폭발/스키드, 시설 상호작용 표시와 월드 미션 표식을 새 렌더러에 연결해야 한다. 실제 게임 로직은 실행되므로 누락된 표시를 기능 없음으로 오해하지 않도록 한다.
2. **조준:** 사선 화면의 마우스 위치를 역변환해 기존 전투 시스템에 전달하는 연결은 미구현. 전투용 완성 씬으로 쓰지 않는다.
3. **미니맵:** 기존 북쪽 위 지도를 그대로 사용한다. 메인 사선 화면과 방향이 다르며 카메라 방향 표시가 필요하다.
4. **가림:** 위의 x+y 근사를 정교하게 바꾸고, 건물 투명화의 급격한 전환을 보간한다.
5. **성능:** 매 프레임 재귀 객체 수집·건물 그리기를 수행한다. 정적 geometry 캐시, 객체 등록 방식, 화면 컬링과 목표 부하 측정이 필요하다.
6. **지역:** 강남 교차로용 프로토타입이다. 다른 구역의 강·교량·바리케이드 등의 전체 표시를 지원하지 않는다.
7. **아트:** 차는 단순 입체 도형이고 건물 대부분 같은 외벽 패턴이다. 최종 방향별 스프라이트·한국형 상가 외벽·간판 밀도·조명·그림자는 추가 제작해야 한다. 간판이 인접 건물에 가려질 수 있다.
8. **결합:** 상위 visual_sample의 HUD 내부 필드와 City._draw_road_segment에 의존한다. M6에서 이름·시그니처를 바꾸면 샘플 연결도 수정해야 한다.
9. **명칭:** project.godot의 예전 가칭은 그대로다. 정식 이름 변경은 저장 경로 이전을 함께 설계해야 한다.

## 다음 권장 작업 순서

- 현재 씬에서 이동·탑승·카메라·추격·사망 복귀를 직접 확인.
- 표시 누락과 조준 역변환 연결, 정렬 개선.
- 동일 교차로에 건물·차량·인물 최종 아트 한 세트 적용.
- 해상도/부하 검증 후 사용자와 스타일을 확정하고 본편 통합 범위를 결정.

본편 3D 전환이나 M6 데이터 재작성은 하지 않았다. 기존 Claude 작업 내용을 삭제·리셋하거나 커밋하지 않았다.

## 후속: 차량 외형 업데이트

`tools/isometric_sample/vehicle_drawer.gd`로 차량 표시를 분리했다. 기존 category·size·paint·roof_color를 사용해 바퀴, 범퍼, 앞뒤 등화, 경사진 세단 유리, 스포츠 스포일러, 택시 표시등, 긴 차체의 버스 창문, 트럭 적재함, 긴급차량 경광등을 구분한다. 게임 물리·차종 리소스는 수정하지 않았다.

대표 8종 확대 도감은 `tools/isometric_sample/vehicle_gallery.tscn`, 이미지 저장은 같은 씬에 `-- --preview-shot`을 붙인다. 결과는 `.screenshots/m7_vehicle_lineup.png`. 도감과 게임은 같은 차량 렌더러를 사용한다. 실행·이미지 저장은 확인했으며 자동 회귀 테스트는 실행하지 않았다.

여전히 코드 도형 기반 초안이다. 참고 포스터 수준의 픽셀 질감·곡면·원형 휠·정교한 차종별 디테일은 미완성이며, 유조차·레미콘·청소차 등은 공통 화물 외형, 헬기는 전용 외형 미구현이다. 실제 브랜드·로고는 가져오지 않았다.

## 후속: 신호등·시설·목적지 표시 연결

`renderer.gd`에 다음 표시를 추가했다. 앞선 ‘표시 누락’ 목록 중 신호등과 아래 항목은 이제 연결된 상태다.

- TrafficController.signal_offsets/light를 사용한 3색 신호등. 원본 TrafficSystem과 동일한 접근 방향·위치 계산, 기둥은 깊이 정렬에 포함한다. 도로 화살표는 해당 신호를 보는 진입 방향이다.
- 실제 Hideout.global_position과 owned/visible에 따른 저장·매물 표시.
- 실제 SprayShop 위치와 PRICE를 사용한 정비 안내. 표시는 즉시 정비 가능 여부를 보장하지 않으며 기존 수배·속도·요금 조건은 유지된다.
- MissionSystem.phones/next_mission/respect 상태에 따른 공중전화 난이도·수락 가능/잠김/완료/진행 중 표시.
- objective_position()이 반환하는 현재 목적지·미션 차량·표적 위치 표시. 목적지가 없으면 표시하지 않는다.
- 시설 안내는 가림에 영향받지 않는 화면 표시이며 지면 원·연결선으로 실제 좌표를 가리킨다. 화면 밖 표시는 생략한다. 가까운 라벨은 위로 이동해 겹침을 줄인다. HUD와의 완전한 충돌 회피·화면 밖 방향 안내는 미구현이다.

기본 장면의 실행·PNG 미리보기만 확인했다. 신호 한 주기, 매물 구매, 정비 실행, 미션 단계 전환 등의 시나리오 테스트는 이번에 실행하지 않았다. 본편 로직·물리·경제 데이터는 수정하지 않았다. 전투 조준·탄환·폭발 등의 표시 연결과 본편 통합은 여전히 남아 있다.

## 사용자 재요청: 포스터와 같은 차량 이미지

사용자는 도형 차량을 완료물로 받아들이지 않았고 포스터와 같은 외형을 명시적으로 요청했다. 내장 image_gen으로 27종 단일 방향 투명 이미지 시트를 생성해 `assets/vehicles/reference_v1/lineup.png`에 저장했다. `vehicle_gallery.gd`는 이 이미지 기반 27종 도감으로 교체했다. 기존 도형 도감 코드는 `vehicle_geometry_gallery.gd`에 보관했다.

**중요: 주행 차량은 아직 도형 렌더러다. 이미지 생성/도감 적용과 주행용 에셋 완료는 구별해야 한다.** 방향별 이미지, 기준점/크기, 차종별 표식 교정, 경광등/도색/파손 상태 처리, 실제 주행 통합이 남아 있다. 생성물은 원본과 픽셀 단위로 동일하지 않다. `assets/vehicles/reference_v1/README.md`에 제작 방법과 남은 작업을 기록했다. 이 단계에서 차량 작업이 모두 끝났다고 보고하지 않는다.

## 후속: 차량 이미지 주행 화면 연결

사용자 요청으로 `vehicle_sprites.gd`를 추가해 2.5D renderer의 차량 그리기에 연결했다. 27개 차량 리소스 파일명으로 시트 영역을 찾아 실제 위치에 그린다. 이미지 영역의 투명 여백은 런타임 초기화에서 계산해 제외한다. 좌우 진행 방향에 따라 수평 반전하고 조종 차량에는 실제 진행 방향 표식을 표시한다. 경광등은 기존 siren 상태에 연결했다. 파괴된 차량·미등록 차종은 기존 도형 렌더러로 돌아간다. 도감 로딩도 Texture2D 리소스 로딩으로 바꿨다.

이제 ‘이미지가 도감에만 적용됐다’는 이전 기록은 최신 상태가 아니다. **주행 장면에도 적용됐지만, 단일 시점 빌보드라는 제한이 있다.** 앞뒤·회전각을 정확히 표현하는 방향별 스프라이트는 아직 없다. 차량 도색 값은 이미지에 반영하지 않으며 충돌 외곽과 이미지 외곽은 완전히 일치하지 않는다. 물리와 게임 로직은 그대로다. 장면 실행·정지 캡처만 확인했고 조작 시나리오 테스트는 실행하지 않았다.

## 후속: 반대 방향 차량 이미지

단일 방향의 이질감에 대한 사용자 지적으로 `assets/vehicles/reference_v1/lineup_rear.png` 27종 후면 시트를 생성했다. `vehicle_sprites.gd`에서 기존 시트와 동일한 순서로 영역을 읽고, 투영된 전방 벡터의 Y 부호에 따라 앞/뒤, X 부호에 따라 좌우 반전을 선택한다. 후면 원본의 진행 방향은 우상단, 전면 원본은 좌하단이다. 이제 뒤로 진행하는 차량도 앞모습으로 표시되는 기존 문제를 줄인다. 정확한 8방향 시트·회전 중 프레임 전환 보간·개별 접지점 교정은 미완성이다. 이미지 생성 프롬프트와 방식은 에셋 README에 기록했다. 자동 테스트는 실행하지 않았다.

## 최신 결정: 차량 이미지 적용 롤백

사용자가 사진/이미지 방식의 자동차 표현을 취소했다. `renderer.gd`의 vehicle_sprites 생성·호출을 제거하고 모든 차량을 기존 `vehicle_drawer.gd` 도형 기반 렌더러로 복구했다. `vehicle_gallery.gd`도 보관된 도형 도감으로 복구했다. 앞·뒤 PNG와 vehicle_sprites.gd는 미사용 자료로 보관한다. 사용자 재승인 없이 이미지 차량을 다시 적용하지 않는다. 건물·신호등·시설 등 다른 2.5D 작업은 유지했다. 이전 이미지 적용 기록은 이 결정으로 대체된다.

## 후속 (Claude Code): 본편 2.5D 적용

사용자 요청("2D로 작업한 거 2.5D로 진행")으로 이 샘플의 투영(같은 BASIS)을 본편 `main.tscn` 전체에 적용했다. 샘플 파일(`tools/isometric_sample/*`)은 수정하지 않았고 독립 실행 그대로다.

- 방식이 샘플과 다르다: 별도 렌더러가 모든 것을 다시 그리지 않고, **화면 변환(canvas_transform)을 사선으로** 바꾼 뒤 각 노드가 자기 `_draw`에서 높이를 더해 그린다. 그래서 도로·자국·탄환·불·표식이 그대로 바닥에 눕고, 마우스·HUD 화살표의 화면↔월드 변환도 자동으로 맞는다.
- `scripts/world/iso_view.gd`: 수식(높이 → 월드 오프셋, 화면 기준 좌표계, 깊이 → z_index). `ChaseCamera`는 Node2D로 바꿨다.
- 건물: `scripts/world/building_view.gd` — 정사각형 조각 단위로 깊이 정렬(샘플의 x+y 근사가 긴 건물 옆에서 틀리던 문제), 벽·창·1층 상가·벽 간판, 지붕은 기존 BuildingDrawer 그림. 가림 반투명은 보간한다.
- 차·사람·헬기·효과·미션 표식·미니맵을 본편 코드에서 2.5D로 그린다. `F9`로 위에서 보기 전환.
- 검증: 기존 테스트 전부 + 새 `tests/iso_test.tscn`. 화면 캡처 `screenshot.tscn -- --only=iso`.
- 남은 것: 다리·고가 높이, 신호등 기둥·공중전화 부스 입체, 최종 픽셀 에셋, 성능 목표 측정.

## 후속 (Claude Code): 본편 차량 입체 모형

사용자가 포스터·27종 시트를 다시 보내며 "이미지를 활용하지 말고 참고해서 각각 만들어 달라"고 했다. 이미지 파일은 게임에 붙이지 않았다(`assets/vehicles/reference_v1/`는 그대로 미사용 보관). 대신 `scripts/vehicle/vehicle_model.gd`에서 28종 각각을 상자·경사 상자·원통 부품으로 코드 모형을 만들어 본편 2.5D 차량으로 쓴다. 참고 그림과 차종 대응은 [12_차량_이미지](12_차량_이미지.md).

## 후속 (Claude Code): 차량 세부 2차

사용자 요청("차량 좀 더 상세하게, Codex 작업 참고")으로 Codex의 확대 도감 방식(`tools/isometric_sample/vehicle_gallery`)을 본편 모형용으로 따로 만들고(`tools/vehicle_gallery.tscn`, 28종·앞뒤·회전), 그 화면을 보며 `vehicle_model.gd`를 다듬었다. Codex 파일은 수정하지 않았다.

- Codex 렌더러에서 가져온 것: 접지 그림자 위 입체, 범퍼·전후 등화로 방향 구분, 경사 유리, 차종별 표시등. 그 위에 모서리 깎기(둥근 차체), 차체색 창 기둥, 문틈·손잡이, 바퀴 아치, 스포크·철제 휠, 트럭 거울 팔·연료통·가드·반사띠, 버스 행선지·문, 특수차 장비를 더했다 (목록은 [12_차량_이미지](12_차량_이미지.md#만드는-방법)).
- 원통을 겹치면 마구리가 비치는 문제 때문에 탱크 테·헬기 띠는 원통 옆면 무늬(`band`)로 그린다.
- 성능: 교통 10분 시뮬레이션 133.9초 (이전 152초) — 모습이 바뀔 때만 다시 그리는 규칙 덕에 부품이 늘어도 느려지지 않았다. 테스트 12개 통과, ★3 도주 6판 중 생존 1·체포 5 그대로.

- 사용자 지적("트럭·대형차 지붕이 잘린 것처럼 보인다")으로 대형차 `height`를 올리고(예: 시내버스 26→34, 타이탄 19→32), 캡·버스·승합·캠핑카 지붕에 둥근 덮개(`crown`)를 얹었다. 높이는 그림에만 쓰인다 (충돌·물리는 그대로).
