# 07. 기술 설계

관련 문서: [08_로드맵](08_로드맵.md) · [02_캐릭터_NPC](02_캐릭터_NPC.md) · [03_차량](03_차량.md)

## 1. 엔진 선택: Godot 4 (GDScript)

| 기준 | Godot 4 | Unity | 자체 엔진 |
|---|---|---|---|
| 2D 탑다운 적합도 | 높음(2D 전용 파이프라인, TileMap, 2D 라이트) | 높음 | 직접 구현 |
| 라이선스 비용 | 무료(MIT) | 매출 조건부 | 무료 |
| 데이터 주도(.tres 리소스) | 기본 지원 | ScriptableObject | 직접 구현 |
| 헤드리스 테스트 | `godot --headless` | 가능(배치 모드) | 직접 구현 |
| 1인~소규모 팀 생산성 | 높음 | 높음 | 낮음 |

**결정: Godot 4.x 안정 버전**. 성능 병목(교통·보행자 대량 업데이트)이 생기면 해당 모듈만 C#/GDExtension으로 내린다.

## 2. 폴더 구조

```

  ai/                  # npc_brain, traffic_ai, police_ai, gang_ai

  ui/

  vehicles/   *.tres   # VehicleType 27종

  weapons/    *.tres   # WeaponType 12종
  districts/  *.tres   # 구역별 스폰 테이블
```

## 3. 핵심 모듈

| 모듈 | 책임 | 비고 |
|---|---|---|
| **Director** | 현재 조종 대상(사람/차량) 단일 관리. 탑승·하차·탈취 전환 | 캐릭터와 차량이 서로 직접 참조하지 않게 한다 |
| **Vehicle** | 탑다운 아케이드 물리: 가속·횡슬립·핸드브레이크 드리프트·차량 간 충돌(질량비) | `RigidBody2D` 대신 커스텀 적분 → 결정적 결과 |
| **LaneGraph** | 도로를 차선 노드·엣지 그래프로. 교차로·신호·버스차로 속성 | 맵 데이터에서 빌드 |
| **TrafficController** | 신호 주기, 교차로 점유 예약(try_reserve/release) | 무신호 교차로 충돌 방지 |
| **TrafficAI** | 차선 추종, 앞차 간격 유지, 사고 후 재합류 | 플레이어 주변 반경만 활성 |
| **NpcBrain** | 상태기계: 배회 → 반응(FLEE/FIGHT/REPORT/TALK) → 복귀 | 반응표는 NpcType 데이터 |
| **PedestrianManager** | NPC 풀링, 화면 거리별 LOD(물리 끄기·숨기기), 공포 전파 | 공간 해시 그리드 |
| **WantedSystem** | 별 0~6, 상승·감쇠 타이머, 이벤트 버스로 범죄 수신 | |
| **PoliceDispatcher** | 별 단계별 세력 스폰(경찰→특공대→헬기→군), 도로 봉쇄 | |
| **MissionSystem** | MissionDef 실행: 목표·타이머·실패 조건·보상 | 스크립트 대신 데이터 + 소수 커스텀 스텝 |
| **GangRespect** | 갱별 존경도, 적대 판정 | |
| **SaveSystem** | 은신처 세이브, JSON 직렬화 | |
| **Radio** | 채널 스트리밍, 뉴스 동적 멘트 | |
| **MapEditor** | 도로·건물·스폰존·미션 마커 배치 → seoul.tres 저장 | 에디터 플러그인 |

### 이벤트 버스
범죄·사망·탈취·폭발은 전부 `EventBus` 시그널로 발행하고, Wanted·Gang·Mission·NPC 반응이 구독한다. 시스템 간 직접 참조를 최소화한다.

```
crime_committed(type, position, witnesses)
npc_killed(npc_type, killer, position)
vehicle_stolen(vehicle, from_npc)
explosion(position, radius)
```

## 4. 데이터 주도 설계
**새 차종·NPC·건물을 추가할 때 코드를 고치지 않는다.** `.tres` 파일 하나만 추가한다.

```gdscript
# vehicle_type.gd
class_name VehicleType extends Resource
@export var id: StringName
@export var category: StringName      # sedan / commercial / bus / special / etc
@export var sprite: Texture2D
@export var palette_variants: Array[Color]
@export var max_speed: float
@export var acceleration: float
@export var brake: float
@export var turn_rate: float
@export var grip: float
@export var mass: float
@export var durability: int
@export var seats: int = 2
@export var has_siren: bool = false
@export var spawn_weight: Dictionary  # district_id -> weight
```

`NpcType`, `BuildingType`, `WeaponType`, `MissionDef`도 같은 패턴. 구역별 스폰 테이블은 `DistrictDef`가 위 리소스들을 가중치로 참조.

## 5. 맵
- 월드 크기(정식): 약 256×256 타일(8192px²) × 구역 7개를 하나의 연속 맵으로.
- 청크 단위(32×32 타일) 스트리밍: 화면 주변 3×3 청크만 노드 활성.
- 높이 레이어 2단(지상 / 고가도로·다리). 레이어 전환은 램프 구간 트리거.
- 맵 원본은 `seoul.tres`(MapData). 절차 생성기는 초기 블록을 굽는 용도, 이후 에디터로 수작업 보정.

## 7. 결정성과 테스트
- RNG는 시스템별 시드 고정 스트림 → 같은 입력이면 같은 결과(버그 재현·테스트 용이).
- **헤드리스 통합 테스트**: `godot --headless --path . res://tests/<name>_test.tscn` 가 종료 코드로 성공/실패 보고.
  - drive_test(차종별 최고속·제동·선회 실측), traffic_test(교차로 무충돌 N분), wanted_test, mission_test, save_test 등
- 마일스톤마다 스크린샷 도구로 대표 장면 캡처해 시각 회귀 확인.
- CI: GitHub Actions에서 헤드리스 테스트 전부 실행.
